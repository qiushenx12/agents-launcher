## 🔴 严重 — 阻塞 macOS 功能

### 1. Claude Observer Hook 脚本仅使用 PowerShell

**文件:** `src-tauri/src/claude_observer.rs`（第 2047-2081 行）

**问题:** Claude Code 的 observer plugin 写入 `session-start.ps1`（PowerShell 脚本），并在 `hooks.json` 中声明 `"command": "powershell.exe"`。macOS 默认没有 `powershell.exe`，所有 Claude Hook 事件（SessionStart、StatusLine 等）将无法触发。

**影响范围:**
- Claude 结构化对话捕获完全失效
- 上下文用量、活动状态、模型切换、权限模式等观察者功能不可用
- 终端日志记录缺失

**修复方向:**
- 检测运行平台，macOS 上生成 `.sh` 脚本并使用 `bash`/`/bin/zsh` 作为 command
- 或在 `hooks.json` 中同时注册 macOS 和 Windows 两套 hook 条目（如果 Claude Code 支持）
- 最低限度：安装 macOS 版 PowerShell（`brew install powershell`），但这不是可接受的长期方案

---

### 2. Workspace Trust 提示检测仅匹配 Windows 路径

**文件:** `src-tauri/src/claude_observer.rs`（第 2782-2800 行）

**问题:** `detect_workspace_trust_prompt` 使用 `looks_like_windows_workspace_path()` 判断路径，该函数仅匹配 `C:\`、`D:\`、`\\` 开头的路径。macOS 路径（`/Users/...`）一律返回 `false`，导致 Workspace Trust 提示永远不会被结构化解析。

**修复方向:**
- 扩展 `looks_like_windows_workspace_path` 为 `looks_like_workspace_path`，同时识别 Unix 绝对路径
- 或在 macOS 分支中调用独立的路径检测函数

## 🟡 中等 — 构建与分发

### 3. tauri.conf.json 仅有 Windows 构建目标

**文件:** `src-tauri/tauri.conf.json`（第 33-51 行）

**问题:**
```json
"bundle": {
  "targets": ["nsis"],
  "icon": ["icons/app.ico"]
}
```
- `targets` 仅包含 `nsis`（Windows 安装程序），macOS 需要补充 `"dmg"` 或 `"app"`
- `icon` 字段仅列出 `.ico`，但 Tauri 2 会根据目标平台自动查找同目录下的对应格式（`icons/app.icns` 已存在，macOS 构建可正常解析图标）
- 缺少 `macos` 段的配置（签名、.entitlements）

**修复方向:**
- 添加 `"dmg"` 和 `"app"` 到 `targets`（或按平台条件配置）
- ~~提供 `icons/app.icns`~~ — **已有** `src-tauri/icons/app.icns`，macOS 分支之前打出的包图标正常
- 补充 `macos` 配置段（签名、entitlements）

1. **Hook 脚本平台适配** — 在 `write_observer_plugin` 中检测平台，macOS 生成 `.sh` 脚本并使用 `zsh`/`bash` 执行
2. **Workspace Trust 路径检测** — 扩展路径识别以支持 Unix 绝对路径
3. **Crate 条件编译** — 确认 `winreg` 和 `windows` 使用 `target.cfg("windows")` 或 `optional = true`
4. **构建配置** — 补充 macOS dmg/app 构建目标和 `.icns` 图标
